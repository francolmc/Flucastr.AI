## Fallos observados

### I3 — el sistema no queda exactamente como estaba

Quedan seis directorios que no existían antes:

- `.claude/agents`
- `.claude/skills`
- `.local`
- `.local/bin`
- `pi-aislado/agents`
- `pi-aislado/skills`

No quedan archivos generados ni enlaces de skills en esta prueba. El archivo personal permanece intacto. Se cuenta como fallo porque el requisito pide restaurar el estado previo, sin excepción para directorios vacíos; el snapshot incluye directorios deliberadamente.

### I4 — simulación con escritura transitoria

Las comparaciones de estado persistente pasan, pero `bash -x instalar.sh --simular` muestra la ejecución de `mktemp` seguida de la asignación exitosa de su ruta a `NUEVO`. El trap elimina ese archivo al salir. Aunque no quedan cambios persistentes, sí se escribió un archivo, contrario al requisito literal. El temporal está confinado a `pruebas/` mediante TMPDIR. No se corrigió el instalador.

### I5 — instalación parcial ante configuración inválida

En ambos casos (`modelos.json` con sintaxis rota y nivel `inexistente`):

- Resolver para Claude Code y Pi: salida 1, error claro, sin modificar el HOME aislado.
- Instalador: salida 1 y el mismo error claro, pero deja `.claude/skills/` con cuatro enlaces y `.flucastr-ai/manifiesto.txt`.
- Causa visible en el código: el instalador enlaza skills antes de resolver el modelo y el trap de salida guarda el manifiesto también al fallar. No se corrigió.
