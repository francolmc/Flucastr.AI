## Steps

### Segment 1 — Story: `./verify` deja `resultado.json` y una utilidad dice «ya verificado» sin falsos verdes
As planner and builder I want `./verify` to write `resultado.json` and a utility that tells me if the tree is already verified, so that nobody repeats a run whose result is known and a failure never counts as success.
Dependencies: Not applicable.
Contracts to keep: `fingerprintCurrent(carpeta)` conserva su firma y devuelve 12 hex o `null`; `core/skills/diagnose/result.mjs` no cambia; el formato de `resultado.json` del contrato no cambia; `tools/run/tree-fingerprint.mjs` no cambia; `./verify` conserva sus pasos y su exit code.
Paths likely to change: `core/skills/diagnose/fingerprint.mjs`, `scripts/kit-verificado.mjs` (nuevo), `verify`, `tests/ya-verificado/ya-verificado.test.mjs` (nuevo; puede moverse dentro de `tests/ya-verificado/`), `tests/diagnosis-suggests/fingerprint-reference.mjs` (la referencia sigue a la fórmula del contrato; debe actualizarse junto con `core/contracts/verification.md`), `core/contracts/verification.md`, `tests/README.md`.
Concrete example of the expected result: tras `./verify` con exit 0 existe `pruebas/.temporales/resultado.json` con `"ok": true, "fallo": "ninguno", "level": "aceptacion"`; `node scripts/kit-verificado.mjs estado --nivel aceptacion` imprime `ya verificado` y `Fingerprint: <12 hex>` y sale 0. Si se cambia el contenido de un archivo nuevo sin seguir, el mismo comando sale 1 con `motivo=huella_distinta`.
Scope: `core/skills/diagnose/fingerprint.mjs`, `scripts/kit-verificado.mjs`, `verify`.
Files: core/skills/diagnose/fingerprint.mjs, scripts/kit-verificado.mjs, verify
WHEN cambia el contenido de un archivo o carpeta sin seguimiento THEN `fingerprintCurrent` cambia (A1).
WHEN `estado` se corre con el árbol intacto y un `resultado.json` válido con `ok: true` THEN sale 0 con `ya verificado`; con el árbol cambiado sale 1 (A2, A3).
WHEN `resultado.json` es ilegible, tiene campos de más tipo o de menos, `ok: false`, `fallo` ≠ `ninguno` o nivel menor THEN nunca sale 0 (A4).
WHEN el mismo árbol ya falló (`ok: false`, misma fingerprint) THEN `estado` sale 3 (A5).
WHEN no hay `HEAD` THEN `estado` funciona con `status` y contenidos sin seguimiento (A6).
WHEN `./verify` termina THEN deja `resultado.json` solo si la corrida fue completa, con la fingerprint de inicio igual a la de cierre; si falló, `ok: false` con `fase` del último paso (A7).

#### Contrato del CLI (`node scripts/kit-verificado.mjs <subcomando> [opciones]`)
- `estado --nivel <rapida|servicio|aceptacion> [--carpeta <dir>=.] [--resultado <ruta>=pruebas/.temporales/resultado.json] [--json]`: aplica la Decisión 1. Imprime `ya verificado` o `verificar (motivo=<...>)`, y siempre `Fingerprint: <12 hex>` (o `no disponible`). Exit 0 / 1 / 3 / 2 según la Decisión 3. Con `--carpeta` que no sea la raíz de un repo: `motivo=sin_huella`, exit 1. `--carpeta` repetida o separada por comas: `motivo=multi_repo`, exit 1.
- `iniciar [--carpeta] [--resultado]`: borra el `resultado.json` anterior (si existe) e imprime la fingerprint de inicio en una línea (`Fingerprint: <12 hex>`).
- `cerrar --nivel <...> --fase <texto> --ok <true|false> --fallo <ninguno|entorno|dependencia|prueba|tiempo> --huella-inicio <12 hex> [--carpeta] [--resultado]`: recalcula la fingerprint; si difiere de `--huella-inicio` o no hay fingerprint, no escribe nada y sale 1 (con aviso en stderr); si coincide, escribe `{fingerprint, level, fase, ok, fallo}` con archivo temporal y `rename` (atómico) en la carpeta de `--resultado`. `--ok true` exige `--fallo ninguno`; `--ok false` exige otro `fallo`; combinaciones inválidas: exit 2 y no escribe.
- Las funciones (`yaVerificado`, `iniciar`, `cerrar`) se exportan para las pruebas; el CLI se ejecuta solo si el archivo es el punto de entrada.
- Usa `fingerprintCurrent` y `leerResultado` (no reimplementa la fórmula) y `tools/spawn/sync-seguro.mjs` o `execFileSync` con stdin `ignore` (paso 19 de `./verify`).

#### Fingerprint con archivos sin seguimiento (Decisión 2)
`git status --porcelain -uall -- . ':(exclude,top)changes/**'`, más `git diff HEAD -- .` (si existe `HEAD`), más, por cada archivo sin seguimiento no ignorado (de `git ls-files --others --exclude-standard -- . ':(exclude,top)changes/**'`), su ruta y su sha256 en orden de ruta, todo hasheado con sha256 y recortado a 12 hex. Enlaces simbólicos: se hashea el destino del enlace (`readlink`), no se siguen. Un archivo ilegible hace que la función devuelva `null`.
