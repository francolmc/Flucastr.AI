# Aislamiento para la línea base

## Comprobado durante el diagnóstico

En este entorno `bwrap` permite crear un espacio de usuario y una raíz temporal. Se comprobó que `/home/franco` no existe dentro de una raíz mínima y que `/Users` puede estar vacío. Node no está en `/usr`: se ejecutó correctamente la versión 24.22.1 montando solo el ejecutable en `/runtime/node`, con `/usr` de solo lectura y sin montar el HOME. Esto prueba los montajes básicos, no prueba que `verify` completo pueda ejecutarse allí.

3. Para crear `/work`, enumera con `git ls-files -z --cached --others --exclude-standard` desde la raíz y copia solo archivos regulares y enlaces del checkout, conservando permisos y directorios; no sigue enlaces. Crea después el fixture sintético indicado arriba. Esta enumeración incluye el estado de trabajo aprobado, no solo HEAD. La copia se vuelve a construir para cada comparación desde el estado vigente, manteniendo fijos HOME, PATH y rutas internas.

Invocar `bwrap` con `--unshare-all`, `--die-with-parent`, `/usr` de solo lectura, enlaces `/bin`, `/lib`, `/lib64` cuando existan, `/proc`, `/dev`, `/tmp` temporal, `/Users` y `/home` vacíos, la copia montada en `/work`, y Node montado en `/runtime/node`. Usar `--clearenv`, `HOME=/home/test`, `PATH=/runtime:/usr/bin:/bin`, `LANG=C.UTF-8` y `TZ=UTC`; ejecutar desde `/work`. Crear HOME y directorio de evidencia antes de los comandos. Comprobar `command -v bash node git tar` y las demás herramientas identificadas por `verify`, y comprobar que no existen el HOME real ni el proyecto personal bajo `/Users`. No montar el checkout original, HOME real ni proyectos externos.

Registrar fuera de la salida sanitizada si `codex` está disponible en el PATH original, sin ejecutarlo con configuración real. Si está disponible, para conservar la rama `execpolicy` montar solo el ejecutable y dependencias estrictamente necesarios de forma verificable, con HOME y CODEX_HOME sintéticos; si no es posible aislarlo o cambia el resultado de la rama, detenerse. Análogamente, detenerse si falta un archivo excluido que alguna prueba necesite o si la ausencia de `.git` cambia su cobertura: no copiar secretos ni suplantar el resultado. La receta es una especificación para construir el arnés, no una afirmación de que ya haya pasado. Guardar la orden `bwrap` efectiva, versiones y resultados de las comprobaciones sin imprimir rutas privadas.
