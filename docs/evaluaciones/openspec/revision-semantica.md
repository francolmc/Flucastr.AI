# Revisión de equivalencia semántica — antes de inferencia

Revisión de artefactos y encargos: por cada caso se generan seis workspaces efímeros (tres casos por dos brazos) a partir del mismo fixture. Cada uno contiene una prueba visible compartida y solo el artefacto del brazo seleccionado: plan kit aprobado o cambio OpenSpec spec-driven. La ruta del artefacto se entrega al worker; los planes tienen aceptación y tareas; los cambios OpenSpec tienen propuesta, diseño, spec delta y tareas pendientes, y se validan con CLI local 1.16.1. Ambos reciben mismas capacidades, condiciones no-git/no-red y requisitos; cambia solo el procedimiento/contexto, no el modelo, esfuerzo, herramientas o límites. El oráculo externo no se incluye en los workspaces. Se regeneraron hashes para el estado congelado actual. Revisión documentada para construcción, no equivale a una aprobación humana de Franco para lanzar el piloto.

- Extractor: fixture textual común con opciones conocidas; API `extractOptions(text)` igual en ambos briefs, deduplicación en orden de primera aparición y no resultado vacío.
- Multiarchivo: módulos `store` y `serialize` separados; API `createTask/readTask/listTasks/taskCount` igual en ambos briefs; requisito integrado de prioridad, valor predeterminado, lectura/listado y rechazo sin inserción.
- Recuperación: mismo modelo de biblioteca con escritura/lectura ya resueltas y rechazo inválido pendiente; API idéntica, registro actual cierra referencia histórica, historial marca pregunta como pasada.
- Ambos brazos: workspace desechable sin `.git`, herramientas equivalente; sin credenciales, servicios ni oráculo editable.

OpenSpec 1.16.1 se inicializó en `artifacts/openspec/generated` con `openspec init --tools pi --language en --no-animation`; el CLI generó seis prompts y seis skills locales. Se compara su skill apply con el kit. Hashes vigentes están en `hashes-iniciales.sha256`. La consulta `openspec instructions apply` devuelve `No changes found` porque OpenSpec exige un cambio activo; no se ejecuta el CLI contra el fixture del trabajador. Se conserva el artefacto aprobado equivalente al nivel del plan.

Comprobación de preparación sin modelos: `prepareWorkspace` es usado por el CLI y self-test; los tres planes kit y los tres cambios OpenSpec se materializan desde el mismo módulo. Las pruebas visibles se copian desde los fixtures compartidos; validación local OpenSpec `instructions apply --json` y `validate --strict` exit 0 por caso. No se han ejecutado modelos. Los hashes atestiguan el conjunto actual, pero deben revisarse por Franco antes de cualquier piloto.
